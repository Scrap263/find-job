# Find Job — план разработки MVP

План рассчитан на небольшую команду. Этапы определяют результат, а не жёсткую
календарную длительность.

## Этап 0. Product discovery

Результат: подтверждён узкий первый рынок.

- провести 8–12 интервью с кандидатами;
- собрать реальные таблицы/способы ведения откликов;
- выбрать регион и 3 первых источника;
- определить 5–10 тестовых профессий;
- измерить ручной baseline поиска и подготовки документов;
- проверить условия использования каждого источника;
- создать набор из 100–200 вакансий для оценки качества.

Критерий выхода: понятны первый пользователь, рынок, источники и измеримый
сценарий, за который пользователь готов возвращаться.

## Этап 1. Фундамент

Результат: запускаемый монорепозиторий и базовая эксплуатация.

- pnpm/Turborepo;
- Next.js, NestJS, worker;
- PostgreSQL migrations;
- Redis/BullMQ;
- S3/MinIO;
- регистрация и сессии;
- конфигурация и секреты;
- structured logging;
- CI: lint, typecheck, unit tests, migrations.

Критерий выхода: новый разработчик поднимает систему одной документированной
командой; staging разворачивается автоматически.

## Этап 2. Профиль кандидата

Результат: подтверждённый структурированный профиль.

- загрузка PDF/DOCX;
- извлечение текста;
- создание атомарных фактов;
- ручное редактирование и подтверждение;
- предпочтения поиска;
- базовое резюме;
- экспорт и удаление данных.

Критерий выхода: ни одно непроверенное AI-утверждение не считается фактом.

## Этап 3. Сбор вакансий

Результат: единая лента минимум из трёх типов источников.

- контракт коннектора;
- Jobicy;
- Arbeitnow;
- Greenhouse;
- Lever;
- импорт вакансии по URL;
- raw storage;
- нормализация;
- расписание и cursor;
- health/status источников.

Критерий выхода: сбой одного источника не останавливает остальные; повторная
синхронизация не создаёт копии.

## Этап 4. Поиск и качество

Результат: релевантная, объяснимая лента.

- синонимы ролей;
- редактируемый поисковый профиль по регионам;
- единый запуск международных источников из дашборда;
- полнотекстовый поиск;
- hard filters;
- извлечение требований;
- детерминированный scoring;
- штраф за несовпадение типа роли (Analyst / Engineer / Manager);
- объяснения;
- дедупликация;
- сохранение и скрытие;
- regression dataset и метрики precision.

Критерий выхода: на тестовом наборе верхние 20 результатов заметно полезнее
простого поиска по точному названию, а причина score доступна пользователю.

## Этап 5. Документы

Результат: проверяемое резюме и письмо под вакансию.

- редактор базового резюме;
- генерация версии;
- связь утверждений с фактами;
- grounded-черновик резюме и письма без неподтверждённых утверждений;
- локальное удаление профиля кандидата и черновика;
- diff;
- письмо;
- ручная правка;
- PDF/DOCX export;
- regression tests против выдуманных фактов.

Критерий выхода: экспорт блокируется при наличии неподтверждённого утверждения.

## Этап 6. Трекер и assisted apply

Результат: полный контролируемый цикл отклика.

- application pipeline;
- Kanban и таблица;
- документы и заметки;
- напоминания;
- переход на оригинальную форму;
- прототип assisted-fill для одного типа ATS;
- экран финальной проверки;
- audit events.

Критерий выхода: внешнее действие невозможно без понятного подтверждения, а
история сохраняет, что и куда было передано.

## Этап 7. Закрытая бета

Результат: данные о реальном использовании.

- 20–50 пользователей;
- onboarding analytics;
- feedback внутри продукта;
- мониторинг качества источников;
- data deletion drill;
- security review;
- резервное восстановление;
- поддержка и обработка инцидентов.

Критерий выхода: пользователи регулярно возвращаются, готовят и подтверждают
отклики; нет критичных ошибок приватности или происхождения данных.

## Что не следует строить первым

- универсальный автокликер по всем сайтам;
- собственный поисковый индекс всего интернета;
- сложную микросервисную платформу;
- мобильное приложение до проверки веб-сценария;
- автоматическую массовую рассылку;
- модель машинного обучения без размеченного набора;
- собственный ATS.

## Ближайший технический спринт

1. создать монорепозиторий и Docker Compose;
2. описать схему БД для профиля, поиска и вакансий;
3. реализовать контракт коннектора;
4. подключить Jobicy и Arbeitnow как первый международный вертикальный срез;
5. показать реальные вакансии в простой ленте;
6. добавить сохранение и статус;
7. написать интеграционные тесты идемпотентного импорта.

После этого будет работающий «скелет», на котором можно проверять интерфейс,
источники и качество поиска до подключения генерации документов.
